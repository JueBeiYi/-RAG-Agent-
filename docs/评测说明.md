# 真实评测与参数实验

系统提供可复跑的检索、生成、Agent 和参数实验工具。所有指标由实际调用计算；首次没有数据时，界面不展示示范分数。

## 1 准备真实语料与人工标注

课程评测选一个具体研究方向，收集 10–20 篇真实论文。系统本身仍保持通用。先在论文库完成导入，在侧栏保存工作区标识。工作区标识用于访问对应数据，不要公开。

生成 80 题人工标注模板，默认四类各 20 题，每类 5 题 dev、15 题 test：

```powershell
.venv\Scripts\python.exe scripts/build_dataset.py --scope YOUR_WORKSPACE_TOKEN --output data/evaluation/cases.jsonl
```

模板全部为 `reviewed=false`，没有编造参考答案和证据，不可直接评测。要逐题改成该方向中的具体可回答问题，填真实参考答案、来源与预期工具，人工核对后才改 `reviewed=true`。题数、难度与题型比例由最终人工审核确认；草案 80 题不等于已完成 80 题标注。

每行是一个 JSON 对象：

```json
{"case_id":"factual-01","question":"论文A在指定测试集报告的准确率是多少？","category":"factual","split":"dev","reference_answer":"填写经原文核对的答案。","relevant_sources":[{"document_id":"替换为实际文档ID","page":3,"paragraph":null,"quote":"替换为能支撑答案的真实原文"}],"expected_tools":["knowledge_qa"],"reviewed":true}
```

`category` 为 `factual/comparison/synthesis/reasoning`。PDF `page` 必须是从 1 开始的物理页码；Word、TXT、Markdown 的页码为空，优先填写真实段落。`relevant_sources` 可以包含多个文档和多处证据。`quote` 不是答案改写，应摘录原文。多证据联合题须列全必要证据。

先调参 dev，再冻结配置跑 test。不要用保留测试集挑选最佳参数。检索评测拒绝未核对、无答案、无证据、文档 ID 或证据无法映射到当前知识库的题目。

```powershell
.venv\Scripts\python.exe scripts/evaluate.py validate data/evaluation/cases.jsonl
```

## 2 三档检索对比

前端“实验与运行记录”可上传 JSONL 并依次运行纯向量、混合、混合加重排序。每次实验记录数据集、语料、配置哈希、索引版本、模型标识、软件版本、逐题原始排名、各阶段分数与耗时。相同工作区的实验与导入由后端队列按序执行，避免边索引边评测。

CLI 示例（PowerShell）：

独立 CLI 直接读取同一本地数据库。运行前应停止 API、确认没有导入或问答任务；前端 HTTP 实验由后端队列管理，可在 API 运行时提交。参数矩阵使用隔离目录，仍应固定原始语料。

```powershell
.venv\Scripts\python.exe scripts/evaluate.py retrieval --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --split dev --mode vector --output artifacts/vector
.venv\Scripts\python.exe scripts/evaluate.py retrieval --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --split dev --mode hybrid --output artifacts/hybrid
.venv\Scripts\python.exe scripts/evaluate.py retrieval --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --split dev --mode hybrid_rerank --output artifacts/hybrid_rerank
.venv\Scripts\python.exe scripts/evaluate.py compare artifacts/vector/results.json artifacts/hybrid/results.json artifacts/hybrid_rerank/results.json --output artifacts/comparison
```

每个检索输出目录包含 JSON 原始记录、CSV、Excel、指标与耗时图、Top-1 分数分布图。分数来自不同检索后端，不是统一的概率值；不得把 RRF 与重排序分数当作同一数值尺度。

指标定义：

- **Hit@5**：前 5 个片段是否命中至少一处标注证据。
- **MRR**：完整返回排名中第一个相关片段名次的倒数。默认返回至少 5 个，通常为 `candidate_k=20`。
- **Recall@5**：前 5 个片段覆盖的标注证据数 / 全部标注证据数。不是“命中的分块数 / 全部相关分块数”。同一证据对应多个片段只计一次。
- **失败题**：检索异常保留错误，Hit/MRR/Recall 计零，避免只统计成功题导致虚高。

证据动态映射到当前分块：文档 ID、页码/段落和标准化原文共同匹配。标准化去除空白并忽略大小写；短引用必须完整出现，长引用跨分块时接受至少 40 个连续标准化字符的重叠。规则导出到结果。这样改分块大小后，标注不依赖旧 chunk_id；应人工抽样检查映射，避免过短或重复摘录造成歧义。

## 3 参数矩阵

扫描在独立目录重建索引，沿用真实文档 ID，不覆盖应用知识库。扫描只允许 dev。资源不足时缩小 grid，不把中断变体当成功结果。

```powershell
.venv\Scripts\python.exe scripts/evaluate.py matrix --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --preset pdf --output artifacts/parser-study
.venv\Scripts\python.exe scripts/evaluate.py matrix --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --preset chunking --output artifacts/chunk-study
.venv\Scripts\python.exe scripts/evaluate.py matrix --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --preset embedding --output artifacts/embedding-study
.venv\Scripts\python.exe scripts/evaluate.py matrix --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --preset retrieval --output artifacts/retrieval-study
```

预设包含：三 PDF 解析器，固定/递归/句段边界三策略 × 256/512/1024，两种课程要求 Embedding，三档检索，生成 temperature/top_p/top_k，路由开关，并行 1/2，缓存开关，上下文 2048/4096。`semantic` 是句段边界分块，不应称为额外模型语义聚类。

生成参数、路由、并行与缓存预设需 `--task generation`：

```powershell
.venv\Scripts\python.exe scripts/evaluate.py matrix --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --preset generation --task generation --output artifacts/generation-study
.venv\Scripts\python.exe scripts/evaluate.py matrix --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --preset routing --task generation --output artifacts/routing-study
.venv\Scripts\python.exe scripts/evaluate.py matrix --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --preset parallel --task generation --output artifacts/parallel-study
.venv\Scripts\python.exe scripts/evaluate.py matrix --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --preset cache --task generation --repeats 2 --output artifacts/cache-study
```

可传 `--grid data/evaluation/grid.json` 自定义 JSON 参数列表。扫描会保留变体错误及汇总 CSV/JSON。PDF 解析对比另记录每文档解析时间、字符数、分块时间、Embedding与索引时间；双栏、表格、公式仍须人工抽样复核，字符多不代表更正确。

## 4 生成、Agent与人工评分

```powershell
.venv\Scripts\python.exe scripts/evaluate.py generation --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --split dev --output artifacts/agent-evaluation
.venv\Scripts\python.exe scripts/evaluate.py generation --cases data/evaluation/cases.jsonl --scope YOUR_WORKSPACE_TOKEN --split dev --rag-only --output artifacts/rag-evaluation
```

每题开启独立会话，避免前题记忆泄漏。默认每题清缓存；`--repeats 2` 同题两次，第二次用于观察缓存是否真实命中，不能仅凭更快就断言命中。输出实际回答、引用、事件、工具成功率、路由覆盖、证据覆盖、Token、耗时与人工评分空字段。

Token 未返回时保留空值；服务估算值按估算呈现。路由指标仅统计填写 `expected_tools` 的题。工具集合完全一致是严格指标，额外合理工具调用可能有益，需人工结合轨迹判定。题目应包含可独立并行的多工具任务才能说明并行收益。

人工质量用 1–5 分分别评：正确性、完整性、引用质量、流畅性；填写 reviewer、失败类型、根因。证据覆盖率不能替代答案正确性。Bad Case至少整理检索、生成、引用、Agent 四类，并记录一次实际改进和固定测试集上的前后对比。

生成报告草稿与台账：

```powershell
.venv\Scripts\python.exe scripts/build_report.py artifacts/vector/results.json artifacts/hybrid/results.json artifacts/hybrid_rerank/results.json --output artifacts/report
```

可追加 `--docx` 输出可编辑 Word 草稿，正式提交前需人工完善并渲染检查版式。脚本只整理实际数据，尚缺人工结论时明确保留待完成项。

## 5 模型准备与演示边界

运行应用不自动下载模型；首次准备明确执行：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-models.txt
.venv\Scripts\python.exe scripts/prepare_models.py --ollama qwen2.5:7b-instruct-q4_K_M
```

脚本缓存 BGE、M3E、重排模型并记录实际 snapshot revision；可把打印的固定模型本地路径写入配置，保证离线复现。Ollama 需提前安装并运行。实际 LLM digest和模型版本应在最终报告补充，不只报告可变标签。

`RAG_PROFILE=demo` 为哈希向量、词覆盖重排、原文抽取的功能检查。可执行 `scripts/seed_demo.py` 导入明确标注的虚构资料并保存工作区标识。它不执行真实大模型推理；结果 `demo=true`、`formal_models=false`，不用于课程性能结论。`dataset_requirement_checks` 只统计数量/题型，不自动声明语料是同一方向的真实论文或已满足课程验收。标注模板和演示资料不能替代真实论文、真实人工答案和真实实验。
