# 课程交付材料生成

`scripts/build_delivery.py` 从实际评测结果、明确的实现验证清单及真实运行截图生成可编辑 Word 与 PowerPoint 文件。材料包括五份主报告、独立的分块、Prompt与Bad Case报告，以及演示PPT。生成器不会用DEMO数据作正式模型结果，不会填写未知身份和工作记录。小样本功能验收与正式课程测试分别标注。

## 运行时

Word authoring使用Codex内置Python和python-docx。PowerPoint使用内置Node的`@oai/artifact-tool`，保持表格、图表与架构图可编辑，不依赖python-pptx。通过workspace dependency loader取得路径；runtime字段可覆盖python、node、node_modules、document_skill、presentation_skill、override_bin、fallback_bin。应用`.venv`依赖与交付authoring运行时分开。

```powershell
& 'C:/Users/28031/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' scripts/build_delivery.py artifacts/delivery-config.json
```

`--documents-only`生成八份Word文件。`--no-render`仅保留源文件，状态中明确尚未视觉验证。默认使用官方技能的DOCX渲染器，通过runtime.soffice与runtime.poppler_dir指定隔离LibreOffice和bundled Poppler的绝对路径，不改PATH、不使用用户桌面Office。工具缺失时保留DOCX和失败状态，不宣称已渲染。另行生成PDF不能证明DOCX布局正确。

## 生成内容与验收

- `课程报告.docx`按项目模板的七部分组织，保留源模板页尺寸、边距与样式。原模板示例日期和完成状态不作为项目事实。
- `系统评测报告.docx`记录实际指标、统计口径、数据性质、版本与哈希。
- `技术设计文档.docx`说明架构、模块、数据接口、部署与边界。
- `用户手册.docx`说明启动、导入、问答、对比、实验和故障处理。
- `实验与BadCase附件.docx`覆盖分块、解析、模型、Prompt参数和失败改进记录。
- `分块策略对比实验报告.docx`记录真实三策略与长度对比，说明统一token计量和证据映射。
- `Prompt模板设计与实验记录.docx`记录证据约束模板和真实生成参数实验，区分执行指标与人工质量评分。
- `Bad Case分析报告.docx`记录四类实际案例、根因、具体修复、复测来源及固定题集前后结果。
- `演示PPT.pptx`为实际文件，包含架构、可编辑数据图表、验证状态和真实界面截图。重复生成使用新版本文件名，保留旧版。
- `交付状态.json`保存来源SHA256、待填写字段、生成文件、视觉验证状态和构建目录。

PPT生成器先导出草稿，调用包完整性与布局检查，再生成最终文件和全部幻灯片PNG。最终交付前逐张查看PNG；Word需标准renderer生成页图并逐页检查。自动结构检查不能证明视觉质量，生成文件也不代表课程语料、人工评分和优化要求已全部完成。

结果条目可增加`scope`字段，明确“20题dev实验”“60题test评测”或“4题标准模式功能验收”。`evidence_files`保存实际验证证据及哈希，`validation_summary`提供验证名称、真实结果和来源。`evaluation_note`统一说明当前评测边界；`findings`、`chunk_findings`、`prompt_findings`、`bad_case_findings`只填写有对应实测支持的结论。

报告生成日期与实际提交日分别保存。`submission_date=待填写`会出现在机器状态待填字段，人工答案评分及题集证据确认也保持待填写。线上功能样本的端到端耗时、冻结检索输入的gen-only用时和不含共享编码的query-only用时分别说明，不能相互替代。图表值按四位小数写入可编辑工作簿，原始JSON保留未舍入指标。
